## Using added points

1. Enter the learner's name, a positive HPS, and a numeric score.
2. Select the small **+** beside that score.
3. Enter positive points and a reason, then select **Apply points**.
4. The score used for calculations updates. A small `+n*` marks the adjustment. The report separately shows **Raw**, **Added**, **Score**, **HPS**, and its explanation.
5. To reverse active additions, reopen **+**, enter a reason, and select **Remove added points**. The former additions remain in report history.

The resulting score cannot exceed HPS. Blank marks and A/L/M/E cannot receive points; enter a numeric score first. Locked periods reject changes. Replacing a score directly, including through paste or bulk editing, ends its active additions and retains them as history. An unchanged value retains its additions.

The pre-existing HPS reduction/recovery behavior remains: lower HPS caps the score; restoring the original HPS restores the recoverable score unless it was explicitly edited. The report identifies a currently capped adjusted score.

Adjustment metadata lives on the learner object in `scoreAdjustments`, alongside the existing numeric score arrays. This keeps existing calculations and Excel/official-summary exports using the effective score once. Normalization, session recovery, JSON serialization and encrypted backups retain adjustment metadata. The metadata is ordinary teacher-editable application data, not an immutable server audit service.

## Reports and dates

- Search by the learner's complete name, select a quarter, and use **Save Quarter … PNG**. One-learner mode also offers **Save this period PNG**.
- Reports contain activity identifiers, titles, competencies/topics when entered, dates, raw and adjusted scores, HPS, attendance letters, explanations, and component/grade summaries.
- Phone reports show responsive text and chart layouts; exported images retain the full report layout.
- Very long reports export as numbered PNG parts in one ZIP. Each image is rasterized in a bounded canvas to avoid excessively tall canvases.
- A/M continue to count as zero; E/L continue to be excluded. Existing grading formulas, weights, transmutation, and QA slot treatment were retained.
- Calendar pickers use the browser/device's current date and locale. They allow past and future dates. Stored dates are `YYYY-MM-DD`.
- Unrecognized older date strings are preserved in saved data and shown in the register for the teacher to replace using the picker. Ambiguous legacy dates are not guessed.
- Cross-period lookup retains the application's name matching. Same-name occurrences are separated and flagged; verify the learner and class before sharing. Renamed learners or reordered duplicate names require teacher review.

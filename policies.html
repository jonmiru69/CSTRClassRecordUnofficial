Your records. Clearly explained.

This is an independent, unofficial class-record tool for authorized CST-R teachers. It supports class rosters, assessment entry, calculated grades, teacher-assisted learner lookup, and Excel, PDF and Word exports.

  1. Sign in to your workspace. Use email/password or Google. New users need the administrator’s registration code; older records use the legacy-claim process.
  2. Create a class and select the grading mode. Quarterly/semestral and trimester workspaces are separate. Confirm the subject weights and calendar with the school.
  3. Enter learners, scores and highest possible scores. Grades are calculated from your inputs. Review missing entries, attendance codes and validation messages before finalizing a period.
  4. Check the save status. Changes have local recovery support. Cloud autosave is batched; use Save changes before changing devices or closing the browser. A successful cloud save is needed for another device to receive updates. Conflicting device edits can require a choice in Settings.
  5. Review and share carefully. Confirm computed grades before locking a period or exporting. Downloaded files are outside the app’s access controls.

How learner lookup works

The search is inside the signed-in teacher workspace. It matches a complete name, ignoring case and extra spaces, against that teacher’s records in the selected grading mode. It can include archived classes. It displays matching grades and assessment progress across periods. It does not verify a parent’s or learner’s identity. Teachers must verify the requester before showing a result; learners with identical names require an additional check against class and roster details.

There is no public student sign-in or public grade-lookup page in this release. No separate lookup audit log or rate limiter is implemented in the supplied application.

Grading references

“Website for Class Record, with respect to DepEd Order No. 15, s. 2026.” The interface also references Order No. 009, s. 2026 for its three-term calendar. These labels describe the application’s references; they are not a certification of compliance. Teachers and the school must verify the applicable grading rules, weights and calendar before official submission.

Privacy policy

Review edition · 20 September 2026. This notice describes the supplied application and proposed operating policy. Formal school/operator approval and a monitored private operator contact must be confirmed before this is treated as a final institutional policy.

Who handles the information

The developer and site operator is Ramelito “Johnmil” Jr. C. Sanchez, LPT. Teachers enter and manage records for their assigned classes. The school retains its institutional responsibilities for academic records. The school and operator must document their controller/processor roles and authorization; an unofficial website does not itself establish these legal roles.

What the application processes

Teacher information includes name, email, account identifier, profile details and an optional teacher photograph. Firebase Authentication handles password credentials and Google sign-in. The class-record database stores profiles and class records rather than authentication passwords.

Learner records include names, class/section/subject details, per-period rosters, scores, highest possible scores and adjustment history, attendance codes (A, M, E and L), and calculated grades. Roster rows can be added; there is no fixed 42-learner limit. The app does not ask for learner photos, LRNs, health records or identity documents. Do not put unrelated information into free-text fields.

Registration uses a code and ticket records with expiry, use status and account identifiers. The supplied implementation sends and stores the submitted registration code in a ticket field; it does not hash that code. Expiry limits ticket redemption, not physical retention.

Purpose and authority

Information supports authentication, class recordkeeping, grade calculation, recovery, synchronization, exports and account administration. Education information is sensitive personal information under Philippine law. The school/operator must establish an applicable Section 13 basis for processing it; ordinary legitimate interest or a teacher’s agreement to website terms does not by itself establish that basis. Use only data that you are authorized to process.

Cloud storage and service providers

The configured Firebase Realtime Database endpoint is in asia-southeast1 (Singapore). This identifies the database location, not the location of every authentication, support, log or backup service. Cross-border processing is subject to the responsible parties’ applicable obligations.

  • Google / Firebase: authentication, account-related services and cloud records. See Firebase privacy information.
  • GitHub Pages: website files and ordinary hosting request information. Class records are not stored in the static repository. See GitHub’s privacy statement.
  • jsDelivr: the Excel library is loaded from this content delivery service. Loading it transmits ordinary network request information. Export generation runs in the browser; no separate export-upload endpoint was identified. See jsDelivr privacy information.

The redesign uses system fonts and removes Google Fonts requests. No advertising, analytics or marketing integrations were identified in the supplied app. Provider logging and authentication storage remain subject to each provider’s terms.

Storage on your device

Your browser may retain full class-record recovery copies, up to 8 local version-history snapshots, preferences and welcome-notice state. Session storage also contains workspace identity information. Firebase manages its own authentication persistence. Logging out does not remove the app’s local drafts or version history. Anyone with access to the browser profile or device may be able to inspect those local copies.

Use a protected device. Before removing this site’s browser data, verify a successful cloud save and secure any needed export. Clearing site data can erase unsynced work and local recovery history; it does not delete cloud records or files already downloaded.

Retention and deletion

The supplied app has no automatic age-based deletion schedule for class records. Records remain until removed through available controls or administrator action, subject to school requirements. Archiving a class hides it from the active list but does not delete it. Revoking access does not delete its records. Local history, downloaded files and provider backups can outlast deletion from the active workspace.

Ticket expiry does not automatically delete ticket nodes. The owner confirms that the school has no fixed record-retention period. Teachers may keep archived classes for necessary, lawful educational or recordkeeping purposes and use deletion when records are no longer needed, subject to applicable duties and school directions. A deletion decision must account for local recovery history, exports and any provider copies; deleting a class is not a guarantee that every copy has been erased.

Your rights and requests

Teachers, learners and authorized representatives may request information, access, correction and other rights available under applicable law, including objection, deletion or restriction where applicable. Requests may require identity and authority checks; legal record-retention duties can limit deletion.

Learners and parents/guardians should use their established teacher or school registrar/administration channel. Teachers should contact the operator through their established private school channel for account and security requests. The owner confirms there is no dedicated school privacy office. Requests should go to the teacher and the school office responsible for the record’s subject matter. A monitored private operator contact still needs to be confirmed; families do not need or receive an account to make a request through those established channels. Do not post learner names, grades, account codes or passwords in public GitHub issues.

Unresolved privacy complaints may be raised with the National Privacy Commission. A public software issue tracker is not a private data-subject request channel.

Children’s data and updates

Teachers enter learner records; children do not receive teacher accounts through this application. The school must establish the appropriate authority and safeguards for minors’ information. Material changes to processing should be reflected in this notice and brought to affected users’ attention. This release does not collect or store legal acceptance receipts.

Terms & conditions

Proposed terms for school/operator review. Opening this page is informational. This release does not represent these draft terms as an already executed agreement.

Use and eligibility

This unofficial service is intended for teachers authorized to maintain the relevant CST-R class records. The school name and crest identify the community served and do not imply formal endorsement. Use your own account and only records you are authorized to process.

Account responsibility

Provide accurate registration details. Use a secure, functioning email account and protect that account, passwords, registration codes and sessions. Teachers are responsible for reasonable care of their credentials; this does not transfer all breach liability to teachers or remove the operator’s own security obligations. Do not share accounts, claim someone else’s legacy records, attempt to bypass access controls, scrape records or use the app for unlawful or unrelated purposes. Report suspected misuse privately to the operator or school.

Academic review

Check rosters, HPS values, score codes, subject weights, rounding, transmutation and term settings before finalizing grades. Automated calculations assist teachers; official grades require teacher and school verification. A locked period is a workflow control, not a digital certification. Exported documents must be checked before submission.

Records and intellectual property

The operator claims no ownership over the personal data entered by teachers. Data-subject rights and institutional recordkeeping obligations apply. School branding remains subject to its owner’s rights. No software license file was supplied with this archive; public availability alone does not grant a license to reuse the code.

Availability and limitations

Network failures, provider outages, browser limits and software defects can interrupt access or synchronization. Use save indicators and maintain authorized backups. The service cannot promise uninterrupted availability, error-free calculations or absolute security. Nothing in these proposed terms excludes mandatory rights or liabilities that applicable law does not permit to be excluded.

Suspension and departure

The operator/school may restrict access for loss of authorization, misuse or security reasons through the available administration process. Arrange lawful handover and retention of academic records before leaving. Account revocation and data deletion are separate actions.

Changes, law and contact

Changes to these terms should be dated and communicated before taking effect. Philippine law and applicable mandatory jurisdiction rules govern. Any unenforceable term does not remove mandatory legal protections. Contact the operator through the established private school channel for service questions; the final contact and effective date require confirmation.

Data protection & safeguards

This section distinguishes application behavior from administrative measures that must be verified by the school and operator. It is not a compliance certification.

Controls visible in the supplied implementation

  • Firebase Authentication supports email/password and Google sign-in.
  • The supplied database rules require authentication and a registration-approval record for class-record access, with UID or legacy-binding checks.
  • Registration code checks are performed by database rules; unauthenticated users are not granted class-record access by those supplied rules.
  • The intended hosted site and configured Firebase connections use HTTPS.
  • Local recovery, version history, save indicators and conflict handling help avoid accidental loss, but create additional copies that require device protection.

Administrative access and known limits

Firebase project administrators with sufficient privileges can access or change stored data through administrative tools. Client rules do not prevent that privileged access. The records are not end-to-end encrypted against the operator. API-key restrictions, deployed rules, account permissions, backups and administrator practices cannot be verified from front-end files alone.

Registration has no application-level IP throttling. Legacy account codes and registration tickets are sensitive. The supplied legacy-binding and approval-recreation rules need a focused server-rule review before making strong isolation or permanent-revocation claims. No security-rule deployment is included in this visual update.

Required operating practice

The school/operator should document who has administrative access, controller/processor responsibilities, the lawful basis for educational data, private request channels, retention, backup disposal, access removal, vendor arrangements and periodic review. Restrict administrative privileges and protect accounts and devices. Never circulate unredacted exports through public channels.

Incident response

Report suspected exposure privately. The responsible parties should contain the incident, preserve evidence, assess affected data and risk, coordinate with the school, document the decision, and remedy the cause. Where notification is legally required, the applicable NPC framework generally requires notification within 72 hours of knowledge or reasonable belief of a notifiable breach. Not every technical fault is a notifiable breach; apply the governing criteria and guidance.

Request handling

Verify the requester’s identity and authority, record the request, locate the relevant records, assess applicable rights and retention duties, provide a secure response, and document the outcome. No automatic 15–30-day service promise or automated deletion workflow has been verified in this application.

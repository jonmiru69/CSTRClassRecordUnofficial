## Grading and stored data

`ASSETS/grading-engine.js` is byte-for-byte unchanged. Attendance treatment, grading weights, transmutation, rounding and trimester calculations continue to use the existing engine. Firebase synchronization, configuration, rules, encrypted backups and official export modules are unchanged. No storage schema migration was introduced. The added UI script only wraps button text for presentation.

Cancelling points changes only the selected learner/activity's effective score and provenance through the existing record operations. The existing HPS cap and recoverable raw-score mechanism remain in force if HPS was reduced below the original raw score. Directly editing a score still starts a new raw score and retains earlier explanations as history. Locked periods remain noneditable.

## Typography research

There is no universal “best small font.” [Material 3](https://developer.android.com/develop/ui/compose/designsystems/material3) uses a 14sp medium body style with 20sp line height; [GOV.UK](https://design-system.service.gov.uk/styles/type-scale/) uses larger body copy and a 16px small style. [Home Office guidance](https://design.homeoffice.gov.uk/design-system/styles/typography) recommends at least 16px for its complex desktop caseworking context. These are context-specific systems, not interchangeable mandates.

This compact desktop record tool uses 14px body text and 13px dense controls, with 12px secondary notes, because the user requested a smaller interface. These sizes are not claimed to be a universal accessibility optimum. Keep browser zoom available. [WCAG resize-text guidance](https://www.w3.org/TR/WCAG21/#resize-text), [visible focus](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), and [24px minimum target guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) informed relative sizing, alternate focus cues and the point-action targets. No formal WCAG certification is claimed.
